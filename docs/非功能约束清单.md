# 非功能约束清单

## 4.1 安全

- 全站使用 HTTPS
- 身份：JWT + Refresh（或单 JWT）
- 关键操作支持二次确认（可选）
- 密码存储：bcrypt / argon2
- 敏感字段加密与脱敏展示（如身份证号）

## 4.2 审计与追溯（强制）

- 所有写操作必须写入 `operation_log`
- 记录 `before` / `after`（JSON 格式）
- 记录操作人、IP、UA、终端类型
- 审计日志不可修改或删除，仅允许归档

## 4.3 数据一致性

- 业务库使用强一致事务保证关键业务一致性
- 设备数据采取最终一致性（事件驱动）
- 禁止把波形大数据直接写入主业务库

## 4.4 可用性与容灾

- 关键服务支持自动重启（如 Supervisor）
- 数据库备份策略：每日全量 + binlog
- 关键配置（字典/阈值规则）版本化管理

## 4.5 性能

- 列表类接口必须分页
- 高频查询字段必须建立索引
- 使用 Redis 缓存热点数据（床位概览、告警摘要）
- 导出与大规模统计采用异步任务处理

## 4.6 可观测性

- 全链路 trace_id（网关/后端/采集/AI）贯通
- 日志格式统一为 JSON
- 关键指标监控：QPS、延迟、错误率、告警堆积、采集丢包率

## 4.7 兼容与扩展

- 设备协议适配层独立（Java 实现）
- AI 服务独立部署（Python 实现）
- 预留时序数据库与对象存储的接口适配能力

## 4.8 合规（工程侧）

- 最小权限原则
- 角色分层：护士 / 医生 / 管理员 / 质控 / 院感
- 数据导出需权限控制并可选水印或脱敏
