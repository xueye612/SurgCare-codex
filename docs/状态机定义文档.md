# 状态机定义文档

## 1.1 总体约定

- 所有状态字段建议使用 `status`（varchar/enum） + `status_reason`（可选）
- 所有状态变更必须写入对应的 `*_status_log`（或统一 `operation_log`）
- 状态变更记录应包含：操作者、时间、来源终端、备注、前后状态、关联对象 ID

## 1.2 床位状态机 — `icu_bed.status`

状态集合：

- `AVAILABLE`：可用空床
- `OCCUPIED`：占用（已绑定在院患者）
- `CLEANING`：清洁/消毒中
- `RESERVED`：预留（预分配床位，尚未入床）
- `MAINTENANCE`：维护/停用

状态流转：

- `AVAILABLE` → `RESERVED`
- `RESERVED` → `OCCUPIED`
- `AVAILABLE` → `OCCUPIED`
- `OCCUPIED` → `CLEANING`
- `CLEANING` → `AVAILABLE`
- `*` → `MAINTENANCE`
- `MAINTENANCE` → `AVAILABLE`

约束：

- `OCCUPIED` 必须有 `current_patient_id`
- `AVAILABLE` / `CLEANING` / `MAINTENANCE` 必须 `current_patient_id = NULL`

## 1.3 患者在 ICU 状态机 — `patient.status`

状态集合：

- `REGISTERED`：已登记（未入 ICU 或待入床）
- `IN_ICU`：在 ICU
- `TRANSFERRED`：转出（转科/转院）
- `DISCHARGED`：出院
- `DECEASED`：死亡

状态流转：

- `REGISTERED` → `IN_ICU`
- `IN_ICU` → `TRANSFERRED`
- `IN_ICU` → `DISCHARGED`
- `IN_ICU` → `DECEASED`

约束：

- 进入 `IN_ICU` 时必须绑定 `icu_unit_id`，建议同时绑定 `current_bed_id`
- 状态变化必须写入 `patient_stay_log`

## 1.4 医嘱状态机 — `medical_order.status`

状态集合：

- `DRAFT`：草稿（可选）
- `ACTIVE`：已下达/有效
- `IN_PROGRESS`：执行中（可选）
- `COMPLETED`：已完成
- `CANCELLED`：已取消
- `SUSPENDED`：暂停（可选）

状态流转：

- `DRAFT` → `ACTIVE`
- `ACTIVE` → `IN_PROGRESS`
- `ACTIVE` → `COMPLETED`（一次性医嘱可直接完成）
- `ACTIVE` / `IN_PROGRESS` → `SUSPENDED`
- `SUSPENDED` → `ACTIVE`
- `ACTIVE` / `IN_PROGRESS` / `SUSPENDED` → `CANCELLED`

约束：

- 每次执行须写入 `medical_order_execution`
- 医嘱完成条件由 `order_type` 决定（一次性/长期/临时/检验/用药/护理等）

## 1.5 护理记录状态机 — `nursing_record.status`

状态集合：

- `DRAFT`：草稿
- `SUBMITTED`：已提交（进入审计）
- `SIGNED`：已签名（护士本人）
- `LOCKED`：已锁定（不可修改）
- `VOIDED`：作废（保留记录、不可删除）

状态流转：

- `DRAFT` → `SUBMITTED`
- `SUBMITTED` → `SIGNED`
- `SIGNED` → `LOCKED`
- `SUBMITTED` / `SIGNED` / `LOCKED` → `VOIDED`（需权限+原因）

约束：

- `SIGNED` / `LOCKED` 不允许编辑，仅允许追加补记（新记录关联原记录）
- 任何修改必须记录 `before` / `after` 到审计日志

## 1.6 告警状态机 — `alarm_event.status`

状态集合：

- `TRIGGERED`：已触发（新告警）
- `ACKED`：已确认（护士/医生确认）
- `SILENCED`：已静默（抑制一段时间）
- `IN_HANDLING`：处置中
- `RESOLVED`：已解除（指标恢复/原因消除）
- `CLOSED`：已关闭（归档关闭）
- `ESCALATED`：已升级（通知升级）

状态流转（建议）：

- `TRIGGERED` → `ACKED`
- `TRIGGERED` / `ACKED` → `SILENCED`（设置 `silence_until`）
- `SILENCED` → `TRIGGERED`（到期后仍异常重新触发）
- `ACKED` → `IN_HANDLING`
- `IN_HANDLING` → `RESOLVED`
- `RESOLVED` → `CLOSED`
- `TRIGGERED` / `ACKED` / `IN_HANDLING` → `ESCALATED`（满足升级规则）

约束：

- 所有状态变化必须写入 `alarm_handle_log`
- 静默必须记录 `silence_until`
- 支持告警聚合：同床位同参数同阈值规则在冷却期内不生成新事件，更新现有事件统计字段（如 `hit_count`）

## 1.7 院感事件状态机 — `infection_event.status`

状态集合：

- `SUSPECTED`：疑似
- `CONFIRMED`：确诊/确认
- `UNDER_CONTROL`：处置中
- `RESOLVED`：已控制/解除
- `CLOSED`：归档

流转：

- `SUSPECTED` → `CONFIRMED`
- `CONFIRMED` → `UNDER_CONTROL`
- `UNDER_CONTROL` → `RESOLVED`
- `RESOLVED` → `CLOSED`
- 允许 `SUSPECTED` → `CLOSED`（排除）

## 1.8 质量事件状态机 — `quality_event.status`

状态集合：

- `REPORTED`：已上报
- `TRIAGED`：已分级/分派
- `RCA_PENDING`：待根因分析
- `RCA_DONE`：根因分析完成
- `IMPROVING`：整改中
- `VERIFIED`：整改验证通过
- `CLOSED`：归档

流转：

- `REPORTED` → `TRIAGED` → `RCA_PENDING` → `RCA_DONE` → `IMPROVING` → `VERIFIED` → `CLOSED`

## 1.9 整改任务状态机（可选独立表） — `rectification_task.status`

- `OPEN` → `IN_PROGRESS` → `DONE` → `VERIFIED` → `CLOSED`

## 1.10 探视预约状态机（如做探视） — `visit_request.status`

- `SUBMITTED` → `APPROVED` / `REJECTED`
- `APPROVED` → `CHECKED_IN` → `FINISHED`
- `APPROVED` → `CANCELLED`
