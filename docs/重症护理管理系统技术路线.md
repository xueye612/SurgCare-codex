# 重症护理管理系统 — 技术路线

## 一、项目定位

构建一套面向 ICU 的重症监护管理系统，目标特性：

- 支持设备参数接入
- 支持未来波形扩展
- 支持 AI 风险预测
- 支持多 ICU / 多院区部署
- 支持完整审计与闭环

采用分层架构设计，保障当前快速交付与未来平滑扩展，避免大规模推翻重构。

## 四、后端技术路线

### 1) 核心业务层 — 技术栈

- ThinkPHP 6
- MySQL 8
- Redis
- Nginx
- Supervisor

负责模块：患者管理、床位管理、护理记录、医嘱闭环、告警管理、院感管理、质控管理、排班管理、权限系统（RBAC）、审计日志系统。

### 2) Redis 的作用

- 告警冷却窗口
- 高频参数缓存
- 在线终端状态
- 分布式锁
- WebSocket 管理

### 3) 设备采集层

技术：Java Spring Boot

职责：设备协议解析、长连接管理、参数标准化、HTTP / MQ 推送到业务层。

### 4) 时序数据库（扩展阶段）

- TimescaleDB — 用于趋势分析与高频数据存储。

### 5) 波形存储（未来阶段）

- MinIO（对象存储） + 数据库存索引用于波形文件管理。

### 6) AI 服务层

技术：Python FastAPI

职责：SOFA 评分、风险预测、感染趋势预测等模型服务。

## 五、系统分阶段实施策略

### 阶段一（MVP）

基础组件：TP6、MySQL、Redis、Java 设备采集（仅参数，暂不存波形）。

交付模块：ICU 床位管理、护理闭环、医嘱闭环、告警中心、基础驾驶舱。

### 阶段二

新增组件：MQ、时序数据库、AI 接入。

### 阶段三

新增能力：波形冷热分层存储、多院区部署、区域质控平台。
