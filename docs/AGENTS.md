# SurgCare-ICU AI Development Rules
==================================================

本文件定义 AI 在本项目中的开发规则。
包括 前端 + 后端 + 设备 + AI 服务。

==================================================
一、系统总体架构
==================================================

前端层
- ICU大屏
- 医生工作站
- 护士工作站
- 感控管理端
- 运营驾驶舱
- iPad 移动端

后端层（TP6）
- 业务逻辑
- RBAC
- 审计
- API

设备采集层（Java）
- 协议解析
- 波形处理

AI层（Python）
- 风险评分
- 预测模型

禁止跨层逻辑。

==================================================
二、目录结构规范
==================================================

/frontend-web
/frontend-ipad
/backend-tp6
/backend-java-device
/backend-python-ai
/docs
/docker

AI 不得新增顶级目录。

==================================================
三、前端开发规范（强制）
==================================================

前端职责：

- 页面展示
- 用户交互
- 调用 API
- 状态显示

前端禁止：

- 写业务规则
- 写审批流程逻辑
- 写告警流转逻辑
- 写感染判断规则
- 写风险计算逻辑
- 本地模拟权限

所有业务逻辑必须在 TP6 层实现。

==================================================
四、权限原则
==================================================

前端权限：

- 只控制显示
- 不作为安全边界

后端权限：

- 必须校验
- 必须记录日志

禁止：
仅在前端控制权限。

==================================================
五、状态机原则
==================================================

状态流转必须：

- 后端控制
- 前端只显示状态
- 不允许前端决定下一状态

例如：

错误示例：
前端 if (status === 'open') 直接改为 'closed'

正确示例：
前端调用 API：
POST /alarm/close

==================================================
六、接口规范
==================================================

所有 API 返回统一结构：

{
  "code": 0,
  "message": "success",
  "data": {}
}

前端不得依赖非标准字段。

==================================================
七、前端数据规范
==================================================

禁止：

- 直接拼接 SQL 风格字段
- 在前端重组业务数据结构
- 在前端推导风险等级

允许：

- UI格式转换
- 日期格式化
- 图表渲染

==================================================
八、UI 架构约束
==================================================

大屏类页面：

- 必须只读
- 不允许直接修改数据

操作类页面：

- 所有提交必须经过后端校验
- 所有操作必须返回明确结果

==================================================
九、设备数据原则
==================================================

前端不得：

- 直接读取设备服务
- 直连 WebSocket 原始波形

必须通过 TP6 统一接口。

==================================================
十、AI 服务约束
==================================================

Python 服务：

- 不直接提供给前端
- 不直连数据库
- 必须由 TP6 调用

==================================================
十一、数据库规范
==================================================

所有表必须包含：

- id
- created_at
- updated_at
- created_by
- updated_by
- deleted_at

禁止物理删除患者数据。

==================================================
十二、日志审计
==================================================

涉及：

- 告警处理
- 感染记录
- 质量事件
- 状态流转

必须记录审计日志。

==================================================
十三、开发流程
==================================================

AI 在生成代码前必须输出：

1. 数据结构
2. 状态机
3. 权限点
4. API 列表
5. 前端调用方式

确认后才可生成代码。

==================================================
十四、禁止事项
==================================================

禁止：

- 在前端实现核心规则
- 在 Java 实现审批流程
- 在 Python 实现数据库写入
- 绕过 API 直接调用数据库

==================================================
十五、性能原则
==================================================

- ICU 实时数据必须异步处理
- 告警必须支持聚合
- 大屏查询必须优化索引
- 禁止全表扫描

==================================================

如 AI 无法确定边界，必须先输出设计方案等待确认。
